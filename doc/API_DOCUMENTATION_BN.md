## ১. আর্কিটেকচার ওভারভিউ

সার্ভারটি উচ্চ পারফরম্যান্স সম্পন্ন **Hono** ফ্রেমওয়ার্কের উপর ভিত্তি করে তৈরি। এটি একই সাথে স্ট্যান্ডার্ড Node.js সার্ভার এবং Vercel Serverless Function রানটাইম সমর্থন করে।

### মূল বৈশিষ্ট্যাবলী:

- **Zero-Cold-Start Optimization**: Vercel Serverless-এ একাধিক সংযোগ বিলম্ব এড়াতে Mongoose-এর নেটিভ MongoClient সরাসরি BetterAuth অ্যাডাপ্টারে শেয়ার করা হয়েছে।
- **Dual Runtime Support**: লোকাল ডেভেলপমেন্টে `@hono/node-server` এবং প্রোডাকশনে `api/index.ts` এর মাধ্যমে Serverless Request Handler চালিত হয়।
- **Strict Data Validation**: রিকোয়েস্ট বডির নির্ভুলতা নিশ্চিত করতে প্রতিটি মিউটেশনে **Zod v4** স্কিমা ভ্যালিডেশন ব্যবহৃত হয়।
- **Backward Compatibility**: পূর্ববর্তী ফ্রন্টএন্ড কোডের সাথে সামঞ্জস্য বজায় রাখতে প্রতিটি মডেল এবং রুটে ফিল্ড এলিয়াস (Aliases) এবং আনভার্সনড রুট (`/api/projects`, `/api/blogs`, `/api/books`) বিদ্যমান।

## ৩. অথেন্টিকেশন ও সিকিউরিটি আর্কিটেকচার

সার্ভারটি আধুনিক পাসওয়ার্ডলেস (Passwordless) সিকিউরিটি মেকানিজম অনুসরণ করে:

### ৩.১ পাসওয়ার্ডলেস ইমেইল ওটিপি (Email OTP)

1. ক্লায়েন্ট `POST /api/auth/email-otp/send-verification-otp` এ ব্যবহারকারীর ইমেইল পাঠায়।
2. সার্ভার একটি সুরক্ষিত ৬ ডিজিটের ওয়ান-টাইম কোড তৈরি করে এবং Resend API-এর মাধ্যমে ইমেইল পাঠায় (৫ মিনিটের মেয়াদ)। লোকাল এনভায়রনমেন্টে কোডটি সার্ভার কনসোলেও প্রিন্ট হয়।
3. ব্যবহারকারী `POST /api/auth/sign-in/email-otp` এ ওটিপি সাবমিট করলে BetterAuth সেশন তৈরি করে এবং সিকিউর কুকি ও বেয়ারার টোকেন প্রদান করে।

### ৩.২ রোল-বেসড অ্যাক্সেস কন্ট্রোল (RBAC)

- অ্যাপ্লিকেশনে দুটি রোল রয়েছে: `admin` এবং `user`।
- ডাটাবেজে ইউজার তৈরির সময় `ADMIN_EMAILS` ভ্যারিয়েবলের তালিকার সাথে মেলানো হয়। তালিকাভুক্ত ইমেইলগুলোকে স্বয়ংক্রিয়ভাবে `admin` রোল প্রদান করা হয়।
- যেকোনো অ্যাডমিন এন্ডপয়েন্টে প্রবেশের জন্য `requireAdmin` (বা `adminOnly`) মিডলওয়্যার কার্যকর থাকে। এটি বৈধ সেশন এবং `role === 'admin'` কিনা তা পরীক্ষা করে। অন্যথায় `401 Unauthorized` বা `403 Forbidden` রিটার্ন করে।

## ৪. ডাটা স্ট্রাকচার ও স্কিমা বিশ্লেষণ

### ৪.১ ব্যবহারকারী ও সেশন (User & Session)

BetterAuth দ্বারা MongoDB-র `user` ও `session` কালেকশনে সংরক্ষিত হয়:

```typescript
interface User {
  id: string; // ইউনিক আইডি
  name: string; // অ্যাডমিনের নাম
  email: string; // ইমেইল অ্যাড্রেস (ইউনিক)
  emailVerified: boolean; // ইমেইল ভেরিফাইড কিনা
  image?: string; // প্রোফাইল ছবির URL
  role: "admin" | "user"; // অনুমতি রোল
  createdAt: Date;
  updatedAt: Date;
}
```

### ৪.৪ টেকনিক্যাল ব্লগ ও প্রবন্ধ (Blogs & Essays)

#### মূল বৈশিষ্ট্য:

- **Lexical ও Block Editor সাপোর্ট**: `content` ফিল্ডে যেকোনো অবজেক্ট, অ্যারে বা মার্কডাউন স্ট্রিং সংরক্ষণ করা যায়।
- **স্বয়ংক্রিয় কভার সিঙ্ক**: `cover` এবং `coverImage` যেকোনো একটি দেওয়া থাকলে প্রি-সেভ হুকে অন্যটিতে অটো-কপি হয়।
- **লিস্ট পারফরম্যান্স অপ্টিমাইজেশন**: ডিফল্টভাবে `getAllBlogs` কল করলে রেসপন্স সাইজ ছোট রাখতে এবং লেটেন্সি কমাতে `content` বাদ দিয়ে লোড হয় (`?includeContent=true` দিলে সম্পূর্ণ বডি আসে)।

```typescript
interface BlogPost {
  id: string;
  title: string;
  slug: string;
  excerpt: string;
  content: any; // Block array or Lexical state
  contentType: "lexical" | "markdown" | "html" | "blocks";
  coverImage: string;
  author: {
    name: string;
    avatar: string;
    bio: string;
  };
  tags: string[];
  category: string;
  readingTime: string;
  featured: boolean;
  featuredType: "large" | "small" | "standard" | "";
  isPublished: boolean;
  publishedAt: string;
}
```

### ৪.৫ বই ও প্রকাশনা সমাহার (Books & Shelf)

বই ও সাহিত্য প্রকাশনার জন্য দুটি মডেল রয়েছে:

1. **BookBundle (`BookBundleModel`)**:
   - `key: "main"` (একক ডকুমেন্ট)
   - `book`: প্রধান হাইলাইটেড বই (`titleBn`, `titleEn`, `author`, `publisher`, `price`, `rokomariUrl`, ইত্যাদি)।
   - `stats`: রিডার পরিসংখ্যান অ্যারে (`[{ value: "৫+", label: "প্রকাশিত বই", icon: "BookOpen" }]`)।
   - `books`: ভার্চুয়াল বুকশেলফে সাজানো বইয়ের তালিকা (`title`, `author`, `coverColor`, `textColor`, `tag`)।

2. **Standalone Book (`BookModel`)**:
   - প্রতিটি বইয়ের জন্য স্বকীয় বিশদ প্রকাশনা রেকর্ড।
   - এতে রয়েছে: `chapters` (অধ্যায় তালিকা), `quotes` (উদ্ধৃতি), `rating` (০-৫), `pages` (পৃষ্ঠা সংখ্যা), `isbn`, `publisher`, এবং `rokomariUrl`/`purchaseLink`।

### ৪.৯ ফাইল আপলোড ও অবজেক্ট স্টোরেজ (Vercel Blob)

- **এন্ডপয়েন্ট**: `POST /api/v1/upload` (শুধুমাত্র অ্যাডমিন)।
- **প্রোটোকল**: `multipart/form-data` (ফিল্ড কী: `file` বা `image` বা `media`)।
- **সর্বোচ্চ আকার**: ১০ মেগাবাইট (10MB)।
- **নামকরণ**: ফাইলের নাম স্বয়ংক্রিয়ভাবে স্যানিটাইজ করা হয় এবং সংঘর্ষ এড়াতে র্যান্ডম সাফিক্স যুক্ত করে Vercel-এর গ্লোবাল সিডিএন-এ হোস্ট করা হয়।
- **ম্যানেজমেন্ট**: ব্লব লিস্ট দেখা (`GET /upload`), ফাইলের হেড মেটাডাটা দেখা (`GET /upload/info?url=...`), এবং ফাইল রিমুভ করা (`DELETE /upload?url=...`) সম্পূর্ণ সমর্থিত।

### ৪.১০ ড্যাশবোর্ড ও সাইট কনফিগারেশন (Dashboard & Dynamic Site Model)

- `SiteModel` দ্বারা সাইটের হেডার ন্যাভিগেশন, লোগো, ফুটার ও সোশ্যাল লিঙ্ক সরাসরি MongoDB Atlas-এ সংরক্ষিত থাকে এবং `PUT /api/v1/site` এন্ডপয়েন্ট দিয়ে অ্যাডমিন যেকোনো সময় আপডেট করতে পারেন।
- ড্যাশবোর্ডের মেট্রিক্সসমূহ (`totalProjects`, `totalBlogs`, `totalBooks`, ইত্যাদি) রিয়েল-টাইমে ডাটাবেজ থেকে গণনা করা হয়।

সার্ভারের প্রতিটি রেসপন্স সুসংহত ও পূর্বানুমানযোগ্য ফরম্যাটে প্রদান করা হয়:

  "success": true,
  "data": { ... },

    "limit": 10,
    "total": 45,
    "totalPages": 5
  }

```

    "slug": { "_errors": ["Slug must only contain lowercase alphanumeric characters and hyphens"] }
  }
}
```

  "success": false,

}
```

}
```

## ৭. Postman কালেকশন ব্যবহারের নিয়মাবলী

প্রজেক্টের রুট ডিরেক্টরিতে **`postman_collection.json`** ফাইলটি রাখা হয়েছে। এটি Postman v2.1.0 স্ট্যান্ডার্ড মেনে তৈরি।

### যেভাবে ব্যবহার করবেন:

1. Postman ওপেন করে **Import** বাটনে ক্লিক করুন এবং `postman_collection.json` ফাইলটি নির্বাচন করুন।
2. কালেকশনের **Variables** ট্যাবে ডিফল্টভাবে দুটি ভ্যারিয়েবল পাবেন:
   - `baseUrl`: লোকাল হোস্ট `http://localhost:5000` (প্রোডাকশন হলে আপনার ডোমেইন দিন)।
   - `bearerToken`: লগইন করার পর এটি স্বয়ংক্রিয়ভাবে সেট হবে।
3. **স্বয়ংক্রিয় লগইন টোকেন সংরক্ষণ**:  
   `2. Authentication & User Profile` ফোল্ডারের **`Sign In with Email OTP`** রিকোয়েস্টটিতে পোস্ট-রেসপন্স টেস্ট স্ক্রিপ্ট যুক্ত করা আছে। আপনি যখনই বৈধ ওটিপি দিয়ে রিকোয়েস্ট পাঠাবেন, রেসপন্স থেকে টোকেনটি স্বয়ংক্রিয়ভাবে কালেকশন ভ্যারিয়েবল `bearerToken`-এ সংরক্ষিত হয়ে যাবে।
4. এরপর যেকোনো অ্যাডমিন রিকোয়েস্ট (যেমন: Create Project, Upload File, Get Dashboard) পাঠানোর সময় আর ম্যানুয়ালি টোকেন কপি-পেস্ট করতে হবে না; স্বয়ংক্রিয়ভাবে রিকোয়েস্ট অনুমোদিত হবে।
